Algorithms

Three engines. One interface.

All algorithms implement ISearch<T> — swap them freely without changing application code.

Recommended

CharSequenceSearch

Builds a suffix trie at index time. Walks the trie at query time for O(k) lookups, where k is the search string length. Ideal for autocomplete and type-ahead with large datasets. Thread-safe concurrent indexing.

Hash-Based

HashSearch

Precomputes hash values for every substring during indexing. Delivers constant-time hash lookups at query time. Best for fixed-length search patterns and high-throughput batch scenarios.

Parallel LINQ

LinqSearch

Leverages Parallel LINQ to search collections concurrently at query time. No upfront indexing cost. Perfect for smaller collections or when items change frequently.

Quick Start

Searching in three lines of C#

Install the NuGet package, create a search instance with your collection, and call .Search().

// 1. Install: dotnet add package FastSearch

using FastSearch;

// 2. Index your collection (one-time cost)
var names = new List<string> { "Alice", "Bob", "Catherine", "Phoenix" };
var search = new CharSequenceSearch<string>(names);

// 3. Search — case-insensitive, sub-millisecond
var results = search.Search("cat");
// results: ["Catherine"]

// Works with any class — just override ToString()
// Or provide a custom index function:
var search2 = new CharSequenceSearch<Person>(
  people,
  p => new[] { p.FirstName, p.LastName, p.Email }
);
How it works

Index once. Search instantly.

FastSearch's CharSequenceSearch algorithm builds a suffix trie for blazing-fast substring lookups.

Provide Your Collection

Pass any IEnumerable<T> to the constructor. FastSearch accepts strings, domain objects, DTOs — anything.

Parallel Indexing

FastSearch builds a concurrent suffix trie from all string representations. Multi-threaded by default. Index millions of items in seconds.

Sub-Millisecond Queries

Type a search string. FastSearch walks the trie character-by-character and returns matching items instantly. No scanning. No regex. Just trie traversal.

FAQ

Frequently asked questions

What is FastSearch?
FastSearch is an open-source .NET library that provides lightning-fast, case-insensitive substring searching across large collections of objects. It includes three algorithms — CharSequenceSearch (suffix trie), HashSearch (precomputed hashes), and LinqSearch (parallel LINQ). It targets .NET Standard 2.1 and is available on NuGet.
How do I install FastSearch?
Run dotnet add package FastSearch in your terminal, or use Install-Package FastSearch in the NuGet Package Manager Console, or search for "FastSearch" in Visual Studio's NuGet UI.
What search algorithms does FastSearch support?
CharSequenceSearch builds a suffix trie at index time for O(k) query-time lookups. HashSearch uses precomputed hash values for rapid substring matching. LinqSearch leverages Parallel LINQ for concurrent searching without upfront indexing.
What .NET versions are supported?
FastSearch targets .NET Standard 2.1, making it compatible with .NET Core 3.0+, .NET 5 through .NET 9, and later versions.
Is FastSearch thread-safe?
Indexing uses ConcurrentDictionary and fine-grained locks for thread-safe parallel construction. The resulting trie is read-only at query time, so searches are inherently thread-safe.
Can I search custom objects, not just strings?
Yes. Either override ToString() on your class, or provide a custom Func<T, string[]> index function that returns the strings to index for each item.
