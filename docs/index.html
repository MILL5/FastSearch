Algorithms

Six engines. One interface.

All algorithms implement ISearch<T>, so you can swap them without changing application code.

Recommended · new in 1.1

NGramSearch

Compressed n-gram posting lists. The smallest index (about 7 bytes per character), about 1 s to build 1M items, and single-digit-microsecond queries. Results come back in input order with no cache.

New in 1.1

SuffixArraySearch

A generalized suffix array with a 1/2/3-character prefix table. Fastest at handing back very broad results, which it memoizes in a bounded cache.

Suffix trie

CharSequenceSearch

Stores a precomputed answer at every trie node, so narrow queries are the fastest of all (about 0.1 µs). Memory grows as O(N·L²): 1.5 GiB for 1M items.

Hash-based

HashSearch

Precomputes a hash of every substring. Query speed is similar to the trie, and it uses the most memory of any algorithm.

No index

LinqSearch

A parallel LINQ scan over lowercased copies made at construction. It has no substring index, but retains a text snapshot that must be rebuilt when indexed data changes.

Baseline

StringSearch

A single-threaded Contains scan with no index. It’s the reference that every other algorithm is tested against.

Quick Start

Searching in three lines of C#

Install the NuGet package, index your collection once, and call Search().

Algorithm specifications: NGramSearch, SuffixArraySearch, CharSequenceSearch, HashSearch, LinqSearch, StringSearch.

// 1. Install: dotnet add package FastSearch

using FastSearch;

// 2. Index your collection (one-time cost)
var names = new List<string> { "Alice", "Bob", "Catherine", "Phoenix" };
var search = new NGramSearch<string>(names);

// 3. Search: case-insensitive, input order, no duplicates
var results = search.Search("cat");
// results: ["Catherine"]

// Given your existing people collection, index several fields:
var peopleSearch = new NGramSearch<Person>(
  people,
  p => new[] { p.FirstName, p.LastName, p.Email }
);
How it works

How NGramSearch stays small and fast

It stores which items contain each short substring, compressed, instead of every possible answer.

Index short substrings

Every 1-, 2- and 3-character substring, plus every 4-character substring shared by 16 or more items, maps to the sorted list of items that contain it.

Compress the lists

Each list stores the gaps between item ids as variable-length integers (about 1–2 bytes per entry), or a bitmap for very common substrings. The index never grows after it is built.

Intersect and verify

Short queries read one list directly. Longer queries intersect the rarest lists, then check the few candidates left against a compact copy of the text.

FAQ

Frequently asked questions

What is FastSearch?

FastSearch is a free, open-source C# library for case-insensitive substring (contains) search over in-memory collections of objects. It provides six algorithms behind one ISearch<T> interface. The recommended one, NGramSearch, indexes 1 million items in about 1 second using 47 MiB of memory and answers typical queries in about 5 µs.

What is the fastest way to search for a substring across a large list in C#?

Build an index once instead of calling string.Contains on every item. On 1 million strings, a Contains scan takes about 37 ms per query and parallel LINQ about 4 ms. A FastSearch index answers the same queries in microseconds: about 5 µs on average with NGramSearch, and about 1.5 µs with the CharSequenceSearch suffix trie, which needs 1.5 GiB of memory to do it.

Which FastSearch algorithm should I use?

Use NGramSearch for almost everything: it has the smallest index (47 MiB for 1M items), builds in about a second, and keeps typical queries in single-digit microseconds. Use SuffixArraySearch if you mostly run 1–2 character queries over millions of items, CharSequenceSearch for the lowest latency on narrow queries over small lists, and LinqSearch for a parallel scan over a text snapshot, or StringSearch to read the source on every query.

How much memory does FastSearch use?

NGramSearch uses about 7 bytes per indexed character on lists of 100,000 items or more, and that doesn't grow as you search. For 1 million passwords (7.5 million characters) that is 47 MiB, compared with 83 MiB for SuffixArraySearch (121 MiB after the measured query workload), 1.54 GiB for CharSequenceSearch and 1.79 GiB for HashSearch.

How does NGramSearch work?

NGramSearch maps every 1-, 2- and 3-character substring (and every common 4-character substring) to a delta- and varint-compressed list of the items that contain it. Queries of up to 3 characters are answered directly from one list, already in input order. Longer queries intersect the rarest lists and verify the few remaining candidates against a compact lowercased copy of the text.

How do I install FastSearch?

Run dotnet add package FastSearch, or Install-Package FastSearch in the Visual Studio Package Manager Console, or search for FastSearch in the NuGet UI.

Which .NET versions does FastSearch support?

FastSearch 1.1 targets .NET 10, the current long-term support release. It no longer targets .NET Standard 2.1, because every .NET runtime that used it (.NET Core 3.x through .NET 9) is out of support or reaches end of support in November 2026. If you need an older runtime, use FastSearch 1.0.16.

Is FastSearch thread-safe?

Concurrent searches can share the completed indexes. Keep source objects and custom index functions safe for concurrent use: StringSearch reads them on every query, and CharSequenceSearch exact-match mode rechecks source fields. SuffixArraySearch synchronizes its result cache.

Can I search custom objects and several fields at once?

Yes. Override ToString() on your class, or pass a Func<T, string[]> that returns the strings to index for each item, such as name, email and company. With NGramSearch, matching fields return each input position once. LinqSearch can return duplicates for multiple matching fields; ordering and duplicate behavior depend on the algorithm.

Is FastSearch free and open source?

Yes. FastSearch is licensed under Apache 2.0. The source is at github.com/MILL5/FastSearch and the package is on NuGet.
